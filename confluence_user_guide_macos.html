Xplor Data Migration Tools — User Guide (macOS)

Version 3.0.2
This guide covers the unified app that replaces all previous standalone tools. You no longer need to download or manage multiple scripts. Everything is available in one application.

Overview

Xplor Data Migration Tools is a desktop application for validating, cleaning, and preparing QikKids data for import into Xplor. It runs entirely in your browser — no coding or terminal knowledge required.

The app includes 5 tools:

ToolWhat it does
Xplor ValidatorValidates migration files, auto-fixes common issues, and generates audit reports
Room & Fee NamesChecks QikKids booking fee and room names against Xplor definitions
Bookings ImportProcesses and cleans recurring and casual booking exports, splits by service
Payment PlansValidates payment plan CSVs, fixes date/weekday formats, splits by service
Balance AdjustmentsMaps balance adjustment data to Xplor services and produces per-centre import files

All tools share a single serviceIDs.csv file that you upload once when the app starts.

Getting Started (macOS)

What you need

  • XplorValidator.app — download from the shared Google Drive / SharePoint folder
  • serviceIDs.csv — the service mapping file for your migration

Step 1 — Download the app

Download XplorValidator.app from the shared Google Drive / SharePoint folder.

Move the file to your Applications folder or Desktop — either location works.

Do not open the file from inside your Downloads folder while the download is still in progress.

Step 2 — First launch (bypass macOS security warning)

Because the app is not distributed through the Mac App Store, macOS will block it on first launch with a security warning.

To open it for the first time:

  1. Right-click (or Control-click) on XplorValidator.app
  2. Select Open from the context menu
  3. A dialog will appear asking if you're sure — click Open
You only need to do this once. After the first launch, you can double-click the app normally.
📷 Screenshot: macOS Gatekeeper warning dialog with "Open" button highlighted
If right-click → Open still doesn't work

On some Macs, the Gatekeeper dialog may not appear even after right-clicking. In this case, use Terminal to allow the app manually:

  1. Open Terminal (press Cmd + Space, type Terminal, press Enter)
  2. Run the following command:
xattr -cr ~/Desktop/XplorValidator.app

If you moved the app to a different folder, replace ~/Desktop/ with the actual path (e.g. ~/Applications/).

After running the command, double-click the app to launch it normally.

Step 3 — Wait for the app to launch

After opening, the app starts a local web server. This takes 5–15 seconds.

Your default browser will open automatically and navigate to the app.

📷 Screenshot: App home page showing 5 tool cards
If the browser doesn't open automatically, type http://localhost:8501 into your browser's address bar.

Step 4 — Upload serviceIDs.csv

Before using any tool, upload your serviceIDs.csv file using the uploader in the left sidebar.

  1. Click Browse files in the sidebar
  2. Select your serviceIDs.csv file
  3. Wait for the green confirmation message
📷 Screenshot: Sidebar with serviceIDs.csv uploader and green confirmation
Important
serviceIDs.csv must be re-uploaded every time you reopen the app. It persists across all 5 tools within the same session, so you only need to upload it once per session.

Tool 1 — Xplor Validator

Validates migration export files against Xplor import rules, auto-fixes common issues, and generates audit reports including cross-service duplicate parent detection.

Navigate to Xplor Validator from the sidebar or home page.

Inputs

InputDescription
Migration fileCSV or XLSX export from QikKids containing parent, child, and emergency contact records
Output folderFolder where all output files will be saved (a subfolder called output/ is created inside)
Import scopeActive only — validate active enrolments only; Active + WaitList — include waitlisted children
Existing service files (optional)Previously validated service files for cross-service duplicate parent detection

Steps

  1. Select your import scope (Active only / Active + WaitList)
  2. Click Browse files and upload your migration file (CSV or XLSX)
  3. Select your output folder using the folder picker
  4. (Optional) Upload existing service files for cross-service duplicate detection
  5. Click Run Validation
  6. Review the results summary and the filterable results table
  7. Collect your output files from the output folder
📷 Screenshot: Validator upload area and scope selector

What the validator checks and fixes

Auto-fixed automatically:

  • State abbreviations normalised (e.g. "New South Wales" → "NSW")
  • Dates converted to standard format
  • Blank first name filled from last name
  • Parent 2 email cleared if it duplicates Parent 1 email — Parent 1 takes priority
  • Emergency contact emails deduplicated within the EC block — if a later emergency contact's email matches an earlier one, the later email is cleared (EC1 takes priority over EC2–EC5)
  • Emergency contact email cleared if it matches Parent 1 or Parent 2 email — a parent who is also listed as an emergency contact will have the duplicate EC email removed
  • Child CRN cleared when it is identical to Parent 1 CRN or Parent 2 CRN — a child and parent cannot share the same CRN
  • Emergency contact boolean fields converted — True/False values in Emergency Contact, Medical Nominee, Collection Nominee, and Excursion Nominee (contacts 1–5) are converted to 1/0

Validated and flagged:

  • Mandatory fields: Service ID, Legacy ID, First/Last Name, DOB, Status, CRN, Room, Enrolment Date
  • CRN format (9 digits + 1 letter)
  • Email, phone, postcode, and boolean field formats
  • Cross-service duplicate parents (matched by name + DOB / contact / email)

Severity levels

SeverityMeaning
ERRORMust be fixed before importing into Xplor
WARNINGReview recommended — may not block import
FIXEDIssue detected and automatically corrected

Tool 3 — Bookings Import

Processes QikKids booking exports into clean, de-duplicated, service-split CSV files ready for import into Xplor.

Navigate to Bookings Import from the sidebar or home page.

Inputs

InputDescription
QikKids booking filesOne or more exports (CSV or XLSX) — recurring and casual files can be uploaded together
Output folderFolder where split output files will be saved
Default booking end date (optional)Applied to any booking with a blank End Date. Leave empty to fall back to 31/12 of that booking's own Start Date year

Steps

  1. Upload one or more QikKids booking files
  2. Select your output folder
  3. (Optional) Set a default booking end date to apply to bookings with a blank End Date
  4. Click Process Bookings
  5. Review the results summary and any conflict warnings
  6. Collect your output files from the output folder
📷 Screenshot: Upload area and results summary showing recurring/casual breakdown

What the tool does

  • Detects and removes exact duplicate booking rows
  • Detects recurring schedule overlaps (same child, overlapping date range, shared booking day)
  • Removes casual bookings that fall within existing recurring patterns
  • Maps QikKids service IDs to Xplor service IDs
  • Reformats dates to DD/MM/YYYY
  • Fills blank End Dates — uses the default booking end date you enter, if set; otherwise defaults to 31/12 of each booking's own Start Date year
  • Splits output by service and booking type (recurring vs casual)

Outputs

LocationDescription
Recurring/[Service_ID]_Recurring.csvOne file per service — recurring bookings
Casual/[Service_ID]_Casual.csvOne file per service — casual bookings
Duplicate_Bookings_Report.xlsxAll exact duplicate rows that were removed
Removed_Casual_Overlaps_Report.xlsxCasual bookings removed due to recurring conflicts
Import order
Always import Recurring files into Xplor first, then Casual files.

Tool 4 — Payment Plans

Validates payment plan CSVs against Xplor Onboarding Tool rules, auto-fixes date and weekday formats, and splits the output by service.

Navigate to Payment Plans from the sidebar or home page.

Inputs

InputDescription
QikKids Service IDs CSVService ID export from QikKids (e.g. 4258_QikKidsOnboardingServiceIds_…csv). Contains the ServiceId and Name columns used to map service names to QK Service IDs.
Payment plan CSVExported from QikKids
Output folderFolder where the split import files and error report will be saved
Column mapping (optional)Auto-detected; expand the Column Mapping section if your file uses custom column names
How service mapping works
The payment plan CSV contains QikKids service names but no service IDs. The tool matches each service name against the QikKids Service IDs CSV to find the QK Service ID, then looks that ID up in the serviceIDs.csv (uploaded in the sidebar) to get the Xplor Service ID and the correct Xplor service name used in the output files.

Steps

  1. Upload the QikKids Service IDs CSV (the service ID export from QikKids for this project)
  2. Upload your payment plan CSV
  3. Select your output folder
  4. (Optional) Expand Column Mapping and adjust if your file uses non-standard column names
  5. Click Run Checker
  6. Review the error summary table
  7. Collect your output files from the output folder
📷 Screenshot: Upload area and column mapping section

Services not in serviceIDs.csv are skipped
If a service name in the payment plan CSV cannot be matched to a QK Service ID in the QikKids Service IDs CSV, or if that QK Service ID is not present in serviceIDs.csv, those rows are skipped and no import file is created for that service. Verify the service name spelling matches exactly.

Tool 5 — Balance Adjustments

Processes balance adjustment exports, maps them to Xplor services by centre name, and produces one per-centre import file using the Xplor Balance Adjustments template.

Navigate to Balance Adjustments from the sidebar or home page.

Inputs

InputDescription
Balance adjustment filesOne or more files in CSV, XLSX, or HTML-exported XLS format
Output folderFolder where per-centre import files will be saved
Template file (optional)Custom template XLSX; if not provided, the built-in template is used

Steps

  1. Upload one or more balance adjustment files
  2. Select your output folder
  3. (Optional) Upload a custom template file
  4. Click Process Balance Adjustments
  5. Review the results — created files and any skipped centres
  6. Collect your output files from the output folder
📷 Screenshot: Upload area and results summary with created files list

What the tool does

  • Accepts CSV, XLSX, and HTML-disguised XLS files
  • Parses Account Name in "Last Name, First Name" format
  • Handles both Credit/Owing column pairs and single signed Amount Due columns
  • Removes rows where Account Name contains "demo parent"
  • Matches centre names to Service Name values in serviceIDs.csv (exact match, case-sensitive)
  • Applies template styling and layout to each output file

Outputs

FileDescription
[Centre Name]_Balance_Import.xlsxOne file per matched centre, formatted using the template
Skipped centres
A skipped centre means the centre name in your input file does not exactly match a Service Name in your serviceIDs.csv. Check spelling and capitalisation if a centre is unexpectedly skipped.

Tips & Troubleshooting

General

IssueSolution
App takes a long time to openNormal — allow 5–15 seconds on first launch for the server to start
Browser doesn't open automaticallyNavigate to http://localhost:8501 manually
"Cannot be opened because it is from an unidentified developer"Right-click → Open on first launch (see Getting Started, Step 2)
Right-click → Open still blockedUse Terminal: xattr -cr ~/Desktop/XplorValidator.app then double-click
serviceIDs.csv not recognisedRe-upload it in the sidebar — it resets each time the app is restarted

serviceIDs.csv

  • Must be re-uploaded every time you reopen the app
  • Once uploaded, it persists across all 5 tools for the rest of that session
  • If a tool reports unmapped or skipped services, check that the centre/service names in your input file match the values in serviceIDs.csv exactly (including spacing and capitalisation)

Output files

  • Output files are never written over your original input files
  • If you run the same tool twice, new timestamped files are created alongside existing ones
  • Check the results summary on-screen before collecting files — it lists every file created and its row count
